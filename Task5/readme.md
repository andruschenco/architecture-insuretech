# Задание 5. Проектирование GraphQL API

## Анализ REST-контракта
- 3 эндпоинта: `/clients/{id}`, `/clients/{id}/documents`, `/clients/{id}/relatives`
- 3 сущности: Client, Document, Relative
- Проблема: множественные запросы → высокая нагрузка на client-info

## Решение: GraphQL
- Единый эндпоинт `/graphql`
- Клиент запрашивает только нужные поля
- Связанные данные (документы, родственники) загружаются по необходимости

## Преимущества
- Снижение RPS в 3 раза
- Уменьшение объёма передаваемых данных
- Гибкость для разных сценариев
- Упрощение версионирования
